# AMretro

لانچر فارسی بازی‌های کلاسیک؛ نام قبلی برنامه **Retro Hub** بود. نسخهٔ جدید ظاهر فروشگاه‌مانند، کتابخانه، صفحهٔ بازی و فایل نصبی دارد و همچنان از همان پنل و API قبلی استفاده می‌کند.

### اندروید بتا

در نسخهٔ منتشرشدهٔ 0.1، اجرای داخلی و دستهٔ لمسی برای GB، GBC و GBA است. سورس شاخهٔ 0.2 اجرای آزمایشی NES و Mega Drive، سه جایگاه ذخیره، انتخاب BIOS شخصی و کنترل یکپارچه را اضافه می‌کند؛ [راهنمای این شاخه](android/README.md) محدودیت‌ها و آزمون‌ها را توضیح می‌دهد. برای سایر کنسول‌ها RetroArch و هستهٔ جداگانه لازم است. تروفی محلی با RetroAchievements رسمی متفاوت است و اجرای داخلی دستاورد رسمی را باز نمی‌کند.

### ویندوز

فایل ستاپ را اجرا کن، مسیر نصب را تأیید کن و مراحل نصب را ادامه بده. میانبر برنامه در دسکتاپ و منوی شروع ساخته می‌شود و حذف برنامه از تنظیمات ویندوز ممکن است. اگر WebView2 روی دستگاه نباشد، ستاپ تلاش می‌کند آن را از مایکروسافت نصب کند؛ برای این مرحله اینترنت لازم است.

ستاپ به‌صورت cross-compile در لینوکس ساخته شده و نصب و حذف آن در Wine آزمایش شده است، اما هنوز روی ویندوز واقعی آزمایش نشده است. فایل امضای دیجیتال ندارد و ممکن است Windows SmartScreen دربارهٔ ناشر ناشناس هشدار دهد.

### اوبونتو و دبیان

فایل `.deb` را با نرم‌افزار نصب بسته باز کن یا در پوشهٔ دانلود این دستور را اجرا کن:

```sh
sudo apt install ./AMretro_0.3.0_amd64.deb
```

پس از نصب، برنامه را با نام **AMretro** از منوی برنامه‌ها یا با دستور `amretro` باز کن. بسته بر پایهٔ Ubuntu 22.04 ساخته شده و به WebKitGTK 4.1، GTK 3 و OpenSSL 3 و دیگر وابستگی‌های درج‌شده در بسته نیاز دارد. مدیر بسته، در صورت موجود بودن وابستگی‌ها در مخزن سیستم، آن‌ها را نصب می‌کند.

## شروع سریع

1. [پنل مدیریت قبلی](https://retro-hub-68aa04.am0u0dev.workers.dev/admin) را باز کن و با اطلاعات مدیریتی خودت وارد شو.
2. در پنل، بازی یا BIOS را اضافه کن؛ برای هر فایل آپلود کوچک در Cloudflare یا لینک دانلود مستقیم را انتخاب کن. کاور، آیکون و گالری هم در برنامه نمایش داده می‌شوند.
3. RetroArch و هسته‌های کنسول‌ها را جداگانه نصب کن. در بخش **تنظیمات** AMretro، مسیر RetroArch، پوشهٔ هسته‌ها و پوشهٔ BIOS را بررسی کن.
4. دکمهٔ همگام‌سازی بالای برنامه را بزن، یک بازی را انتخاب کن و **دانلود و نصب** را بزن. BIOSهای منتشرشدهٔ همان کنسول پیش از دانلود بازی بررسی می‌شوند. BIOS غایب ابتدا دانلود و نصب می‌شود؛ فایل موجودِ یکسان دوباره دانلود نمی‌شود.
5. در بخش **دکمه‌ها** چیدمان عمومی صفحه‌کلید و دسته را ذخیره کن؛ از صفحهٔ یک بازی نصب‌شده هم می‌توانی **تنظیم دکمه‌های بازی** را برای همان بازی ذخیره کنی. تغییرات در اجرای بعدی اعمال می‌شوند. حذف تنظیم اختصاصی بازی آن را به تنظیم عمومی برمی‌گرداند. در سورس جدید پیش‌فرض جهت‌ها `W/A/S/D` است؛ فایل‌های دسکتاپ منتشرشدهٔ 0.3 هنوز این تغییر را ندارند.

کاتالوگ فعلی شامل ۱۰ کنسول است و هنوز بازی یا BIOS منتشرشده ندارد. تا زمانی که در پنل بازی اضافه نکنی، کتابخانهٔ برنامه خالی خواهد بود.

## داده‌ها و محدودیت‌ها

- برای نگه‌داشتن داده‌های نسخهٔ قبلی، شناسهٔ داخلی برنامه و نام دیتابیس تغییر نکرده‌اند. تنظیمات و کتابخانهٔ قبلی با تغییر نام حفظ می‌شوند؛ این مهاجرت روی لینوکس آزمایش شده است. حذف نصب نیز فایل‌های شخصی و کتابخانه را عمداً پاک نمی‌کند.
- سقف هر فایل بازی، BIOS یا تصویر که در پنل Cloudflare آپلود می‌شود **۱٬۰۰۰٬۰۰۰ بایت** است. برای فایل بزرگ‌تر، لینک دانلود مستقیم بدون صفحهٔ واسطه یا کپچا لازم است. فایل و تصویر در Supabase ذخیره نمی‌شوند.
- ZIP و 7z پشتیبانی می‌شوند؛ RAR پشتیبانی نمی‌شود. بازی‌ها، BIOS، خود RetroArch و هسته‌ها همراه برنامه نیستند؛ فقط از فایل‌هایی که حق استفاده از آن‌ها را داری استفاده کن.
- برای هر کنسول همهٔ BIOSهای منتشرشده در پنل بررسی می‌شوند؛ پنل فعلی هنوز انتخاب «اجباری/اختیاری» یا منطقه ندارد، بنابراین BIOSهای ناسازگار یا جایگزین با مسیر یکسان را هم‌زمان منتشر نکن. برای PS1 اگر هیچ BIOS منتشرشده یا فایلی با نام شناخته‌شده در پوشه system پیدا نشود، نصب بازی متوقف و راهنما نمایش داده می‌شود. هسته‌ها و مناطق ممکن است BIOSهای متفاوتی بخواهند؛ داشتن فایل به‌تنهایی سازگاری را تضمین نمی‌کند.
- هنگام وجود SHA-256، فایل دانلودی بررسی می‌شود. برای آرشیو، هش مربوط به خود آرشیو است و فایل‌های استخراج‌شده با فهرست و هش جداگانه کنترل می‌شوند. فایل متفاوت یا تغییرکرده بازنویسی نمی‌شود. اگر هش ثبت نشده باشد، برنامه نمی‌تواند اصالت فایل موجود را تأیید کند.
- دکمه‌های دسته ابتدا به RetroPad منطقی نگاشت می‌شوند؛ RetroArch معمولاً دسته‌های دارای پروفایل را خودکار می‌شناسد. بعضی دسته‌ها یا آنالوگ‌ها نیاز به تنظیم دستی در Settings → Input → RetroPad Binds دارند. گرفتن دکمه در AMretro به پشتیبانی gilrs و نگاشت منطقی سازگار با RetroArch وابسته است.
- دانلود، ادامهٔ دانلود با Range، بررسی SHA-256، استخراج و نصب، و نگاشت صفحه‌کلید با RetroArch واقعی در لینوکس بررسی شده‌اند. دستهٔ فیزیکی و اجرای برنامه روی ویندوز واقعی هنوز آزمایش نشده‌اند.
- تنظیم دکمه‌ها روی همان دستگاه ذخیره می‌شود و فعلاً بین حساب و دستگاه‌های دیگر همگام نمی‌شود.
- ورود به حساب اختیاری است. برای ثبت‌نام عمومی هنوز باید سرویس ارسال ایمیل Supabase تنظیم شود.
- توکن Cloudflare و رمز اولیهٔ پنل قبلاً در گفتگو استفاده شده‌اند؛ برای امنیت آن‌ها را تغییر بده.

## بازسازی از سورس

سورس برنامه در `desktop/` و پنل/API در `worker/` است. Rust stable، پیش‌نیازهای Tauri v2 و وب‌ویوی سیستم لازم‌اند. فایل‌های فونت Vazirmatn و مجوز OFL کنار سورس ارائه شده‌اند. فایل Microsoft Edge WebView2 Bootstrapper موجود در `desktop/installer/vendor/` از مایکروسافت دریافت شده و checksum آن در اسکریپت ساخت کنترل می‌شود.

برای بررسی برنامه:

```sh
cd desktop/src-tauri
cargo test --locked --lib
cargo build --locked --bin retro-hub-desktop
```

برای تولید بستهٔ لینوکس، اجرایی x86_64 را در Ubuntu 22.04 بساز و مسیر آن را به `desktop/scripts/build-linux-deb.sh` بده. برای ستاپ ویندوز، اجرایی x64 و `WebView2Loader.dll` متناسب با آن و ابزار Unicode NSIS 3 لازم است؛ `desktop/scripts/build-windows-installer.sh` بسته را تولید می‌کند. ساخت cross-compile ویندوز آزمایشی است و جای تست روی ویندوز را نمی‌گیرد.

برای پنل، Node.js نسخهٔ ۲۲ یا جدیدتر و دسترسی Cloudflare لازم است:

```sh
cd worker
npm ci
npm run typecheck
npm test
```
